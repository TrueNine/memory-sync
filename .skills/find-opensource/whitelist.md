# Open‑Source Selection Whitelist (Preferred Candidates)

> This file lists projects, tech stacks, and ecosystems that the user **strongly prefers**. During search and recommendation you **MUST** read it: under business and basic‑constraint alignment, whitelist entries should be **prioritised for evaluation**, given higher weight when candidates are close, and described in more detail.

## Usage

- Whitelist means “**preferred / prioritised**”, **not** “the only options”.
- If final recommendations **do not follow** whitelist directions, the Agent **MUST** explicitly explain why (e.g. business mismatch, too high maintenance cost, deployment conflicts).
- When whitelist and blacklist conflict, **blacklist wins** (safety and value baselines first).

## Stacks / Ecosystems

- Mozilla / Firefox ecosystem
  - Preferred scope: Projects and tools related to Web standards, browser compatibility, privacy, and the open Web, such as Firefox and its surrounding ecosystem.
  - Reasons: Long‑term commitment to open standards, user privacy, and community‑driven open source; more trustworthy in values and technical direction than many commercial giants.

- Next.js 16 stack
  - Preferred scope: Web / SaaS / admin / landing‑page templates and scaffolds built on Next.js 16, especially those supporting App Router and Server Components.
  - Reasons: Good balance across performance, developer experience, and ecosystem maturity; naturally fits Vercel / edge deployment; currently a stable, high‑leverage new‑generation choice in the Next.js ecosystem.
