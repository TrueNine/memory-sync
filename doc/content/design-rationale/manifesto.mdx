# 为什么会有这个工具

README 对 `croessweave` 的核心定位说得很直接：这不是一个等着平台最终收敛到统一标准的工具。它是一个在工具割裂、接口私有、访问机会分配不均的现实世界里依然能工作的 “tool-rat”。

## 这个项目不承诺什么

它不承诺：

- 某个特定 IDE 或 CLI 最终一定会给你一个官方统一入口
- 某个平台会永远可靠地替你保存工作记忆
- 复制粘贴几段 prompt 就等同于真正的迁移

## 这个项目真正想做什么

它的目标是：

1. 把当前散落在各个工具里的规则源提取出来。
2. 为这些规则源提供一套一致的编写模型。
3. 再把它们投递回不同工具各自要求的原生位置。

## 为什么这必须是一个 sync 系统，而不是模板仓库

如果只有一个模板仓库，你仍然要手动处理这些事情：

- 决定每个工具的输出应该写到哪里
- 决定哪些内容是全局的，哪些是项目级的
- 决定如何移除旧产物
- 决定如何避免多套配置互相踩踏

`croessweave` 的意义，就在于把这些决策前移到声明式配置和 source 文件结构中。

## 为什么文档也必须一起重写

如果文档继续保留那种无法映射回真实实现的松散叙事，文档本身也会变成新的残留物。重写 docs-site，本质上就是把同样的纪律应用到文档上：让文档能够对照实现进行验证，而不是继续漂移。
