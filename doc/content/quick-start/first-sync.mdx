# 第一次同步

## 推荐顺序

```sh
tnmsc dry-run
tnmsc
```

第一步只预览会写出多少文件和目录，不做真实写入。第二步才执行默认同步管线。

## 为什么一定先 `dry-run`

当前 CLI 的 `dry-run` 会遍历所有输出插件，汇总每个插件声明的目标文件与目录数量，并明确返回：

```text
Dry-run complete, no files were written
```

这一步是你确认：

- 输出范围没有跑错到意料外的项目
- 插件组合没有生成不该存在的目标
- 新增的 rules / skills / commands 命名没有撞车

## 正式同步之后看什么

同步后重点检查三类产物：

1. 目标工具原生配置，例如 `AGENTS.md`、`CLAUDE.md`、Cursor / Windsurf / Warp 等对应输出。
2. 技能、命令、sub-agent 的导出目录是否与配置一致。
3. README / IDE 配置这类“附带输出”是否符合项目边界。

## 如果发现目标文件不对

- 先不要手动删一堆输出文件。
- 回头检查 [输出范围](/docs/reference/output-scopes) 和 [清理保护](/docs/reference/cleanup-protection)。
- 需要清除残留时，优先使用 [dry-run 与 clean](/docs/operations/dry-run-and-clean) 的流程，而不是裸删。
