# 规则

## 规则适合什么

规则更适合长期约束，比如：

- 目录职责
- 架构边界
- 代码风格的红线
- 审查和交付纪律

它们比命令更稳定，也比 skills 更偏约束表达。

## 当前路径约定

默认输入路径：

```text
rules/
```

默认输出路径：

```text
dist/rules/
```

## 规则与输出范围的关系

当前模型允许你为 `rules` 分配自己的 `project` 或 `global` 输出范围，这非常重要。有些工具需要全局规则，另一些则只应该接收项目本地规则。

如果规则写到了不该去的地方，先别怪规则文件本身。优先检查 [CLI / 输出范围](/docs/cli/output-scopes)。
