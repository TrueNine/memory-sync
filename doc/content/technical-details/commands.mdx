# Commands

## What Commands Are Good For

Commands are a good fit for operations that:

- are reused frequently
- have a clear execution goal
- are easy to trigger with short text

They work best as concise operation entrypoints.

Typical examples include generating release notes, rechecking a class of errors, or reshaping context into a specific format.

## Current Path Convention

Default input path:

```text
commands/
```

Default output path:

```text
dist/commands/
```

## What `commandSeriesOptions` Does

The schema lets `commandSeriesOptions`:

- set `includeSeriesPrefix`
- override `includeSeriesPrefix` or `seriesSeparator` per plugin

That means commands are not just flat output files. They can also carry series-based naming rules. Think of it as grouping and naming control for a command family rather than a single-file naming rule.
