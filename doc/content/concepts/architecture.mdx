# 架构边界

## 当前 monorepo 的真实角色分工

仓库根说明把边界写得很清楚：

- `cli/` 是用户入口，也是 `tnmsc` 二进制、crate 与 TypeScript 接口所在位置。
- `libraries/` 是 Rust-first library 区域，当前主要包含 `logger/` 与 `md-compiler/`。
- `gui/` 是 Tauri 调用层，负责调用 `tnmsc` crate，并不是主导领域模型的地方。
- `doc/` 是支持性文档层，不负责核心同步逻辑。

## 为什么强调 Rust-first / NAPI-first

项目当前的技术方向不是“完全抛弃 TypeScript”，而是：

- Rust 负责长期核心能力
- NAPI 负责把核心能力暴露给 Node / TypeScript
- TypeScript 主要承担接口暴露、配置装配、桥接运行时与声明性描述

这决定了两条纪律：

1. 不再引入新的纯 TypeScript fallback 作为长期方案。
2. 新能力优先考虑 Rust crate 或 Rust-backed NAPI，而不是继续让 TS 成为最终归宿。

## `doc/` 在整体里是什么

`doc/` 不是架构真源，只是对真实仓库的解释层。也就是说：

- 文档不能发明不存在的目录职责。
- 文档不能把旧 GUI 叙事继续包装成当前事实。
- 文档必须跟随真实的 CLI / Schema / 插件实现更新。
