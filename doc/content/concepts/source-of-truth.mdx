# 单一真源模型

## 什么是“真源”

在这个项目里，真正长期应当维护的是：

- 你的 MDX prompt 源
- 你的 aindex 目录组织
- 你的全局配置与项目级 `plugin.config.ts`

目标工具里的产物，例如 `AGENTS.md`、`CLAUDE.md`、`.cursor/*`、README 导出内容，都只是**输出**。

## 为什么输出不能反过来当源

因为输出目标天然碎片化：

- 各工具格式不同
- 命名、路径、元数据字段都不同
- 某些工具甚至会随版本调整布局

如果把这些输出文件本身当作主维护面，你就会重新回到复制粘贴与多处分叉维护的老路上。

## 这也解释了“为什么要全量清理”

README 中强调 full wipe / full clean，不是为了激进，而是为了让输出保持**可计算**。只要输出不是完全由真源推导出来，残留历史文件就会慢慢污染你对系统真实状态的判断。

## 一句话总结

源应该是稳定、可读、可版本控制的；输出应该是可重建、可删除、可审计的。`memory-sync` 的价值就在于把两者隔离清楚。
